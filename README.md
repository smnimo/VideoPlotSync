# VideoPlotSync

動画の下に時系列プロットを縦に結合し、プロット上に「現在の動画の位置」を赤線で示した動画を作るスクリプトです。

```
┌──────────────────┐
│      動画         │
├──────────────────┤
│  プロット  ┃赤線   │  ← 動画の再生位置に合わせて動く
└──────────────────┘
```

## 必要なもの

- Python 3.9 以上
- ffmpeg / ffprobe（`ffmpeg`・`ffprobe` コマンドに PATH が通っていること）

## セットアップ

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 使い方

```bash
python video_plot_sync.py --video input.mp4 --csv data.csv -o output.mp4
```

fps とフレーム数は ffprobe で自動的に調べます（調べた値は実行時に表示されます）。

### 入力 CSV

1 行に `index,value` の組を書きます。`index` は動画のフレーム番号です（秒で書く場合は `--index-unit sec`）。
ヘッダ行など数値に変換できない行は自動で読み飛ばします。行の順番はばらばらでも構いません。

```csv
index,value
0,0.12
1,0.15
2,0.20
...
```

### fps・フレーム数の自動検出

`--fps` / `--frames` を省略すると、ffprobe で次のように調べます。指定した場合はその値を優先します。

- **fps**: `avg_frame_rate`（平均フレームレート）を使います。
- **可変フレームレートの検出**: `avg_frame_rate` と `r_frame_rate` が 1% 以上違うか、「フレーム数 ÷ 動画の長さ」が fps と 1% 以上違う場合は、可変フレームレート（スマホ動画など）とみなして警告を出します。後者の場合、fps を自動検出しているときは「フレーム数 ÷ 長さ」の実測平均 fps を使います（mkv などはヘッダの `avg_frame_rate` が実際と違うことがあるため）。可変フレームレートの動画では「フレーム番号 ÷ fps = 時刻」が厳密には成り立たないため、赤線が少しずれることがあります。気になる場合は事前に固定フレームレートに変換してください（例: `ffmpeg -i in.mp4 -fps_mode cfr -r 30 out.mp4`）。
- **フレーム数**: メタデータの `nb_frames` → 取れなければパケットを数える（`-count_packets`、デコードしないので速い）→ それも駄目なら `duration × fps` の順に試します。

`--fps` を指定したくなるのは、CSV のフレーム番号が別のツール（顔検出など）の解釈した fps に基づいていて、そちらに合わせたいときです。`--frames` は先頭だけ試しに出力したいとき（例: `--frames 300`）にも使えます。

### オプション

| オプション | 既定値 | 説明 |
|---|---|---|
| `--video`, `-i` | （必須） | 入力動画 |
| `--csv`, `-c` | （必須） | `index,value` の CSV |
| `--fps` | 自動 | 動画の fps（省略時は ffprobe で検出） |
| `--frames` | 自動 | 出力するフレーム数（省略時は動画のフレーム数を検出） |
| `--output`, `-o` | `output.mp4` | 出力動画 |
| `--index-unit` | `frame` | CSV の index の単位（`frame` / `sec`） |
| `--step` | `0` | 1 画面に表示する秒数。`0` なら動画全体を 1 画面に表示。長い動画では例えば `60` にすると 60 秒ごとに表示区間が切り替わる |
| `--xtick` | `0` | x 軸目盛りの間隔 [秒]。`0` なら自動 |
| `--gap` | `0.5` | この秒数以上データが抜けている所で線を切る。`0` なら全部つなぐ |
| `--mean` / `--median` | なし | 移動平均 / 移動中央値で平滑化 |
| `--window` | `1.0` | 平滑化の窓幅 [秒] |
| `--title` | なし | プロットのタイトル |
| `--ylabel` | `value` | y 軸ラベル |
| `--ymin`, `--ymax` | 自動 | y 軸の範囲 |
| `--invert-y` | なし | y 軸を上下反転（順位など、小さいほど上に描きたいとき） |
| `--line-width` | `3` | 赤線の太さ |
| `--width` | `800` | 出力動画の幅 [px]。動画もプロットもこの幅にそろえる |
| `--fig-width`, `--fig-height` | `15`, `4` | プロットの大きさ [inch]（縦横比が決まる） |
| `--dpi` | `100` | プロットの解像度 |
| `--crf` | `23` | x264 の画質（小さいほど高画質・大きいファイル） |
| `--no-audio` | なし | 音声を含めない（既定では元動画の音声をそのまま入れる） |

### 例

5 分ごとに表示区間を切り替え、1 秒の移動平均をかける:

```bash
python video_plot_sync.py -i face.mp4 -c smile.csv \
  --step 300 --xtick 10 --mean --window 1 --ylabel "smiling intensity" -o face_smile.mp4
```

## 仕組み

- プロットは表示区間が変わるときだけ全体を描画して背景として保存し、フレームごとには背景を戻して赤線だけを描くので高速です。
- プロットのフレームは rawvideo として ffmpeg の標準入力に流し、元動画と同じ ffmpeg の中で縮小・`vstack` で結合するので、中間ファイルは作りません。
- 出力の長さは、動画と `--frames` のうち短い方になります。
